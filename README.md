# Announcements UK Platform

Цей репозиторій містить початкову реалізацію бекенду для платформи «Оголошення Англії».

## Backend (Node.js / Express + TypeScript)

### Основні можливості
- Реєстрація та авторизація користувачів з JWT-токенами.
- Управління категоріями та підкатегоріями з мультимовними перекладами.
- Створення, поновлення та оновлення оголошень з перевіркою квот, автоматичним завершенням і керуванням закріпленням.
- Облік платежів (створення платіжних записів) і отримання історії користувача, у тому числі оплати за pin/refresh.
- Простий файл-базований сховище даних для прототипування.
- Базовий чат між покупцем та власником оголошення з непрочитаними лічильниками.

### Як запустити
1. Встановіть залежності:
   ```bash
   cd backend
   npm install
   ```
2. Створіть файл `.env`, використавши `.env.example` як шаблон. За потреби налаштуйте бізнес-параметри (тривалість безкоштовної публікації, ціни pin/refresh тощо).
3. Запустіть сервер розробки:
   ```bash
   npm run dev
   ```
4. API буде доступне на `http://localhost:4000` (порт можна змінити в `.env`).

### Структура API
- `POST /api/auth/register` — реєстрація користувача.
- `POST /api/auth/login` — отримання токену.
- `GET /api/categories` — публічний список категорій з деревом підкатегорій.
- `POST /api/categories` — створення категорії (доступно для ролей `admin` та `moderator`).
- `PUT /api/categories/:id` — оновлення категорії (роль `admin`/`moderator`).
- `GET /api/listings` — перелік оголошень з фільтрами.
- `POST /api/listings` — створення оголошення (авторизовані користувачі).
- `PUT /api/listings/:id` — оновлення оголошення.
- `POST /api/listings/:id/pin` — закріплення оголошення у топі з урахуванням оплачуваних слотів.
- `POST /api/listings/:id/refresh` — платне оновлення (refresh) з добовими лімітами.
- `POST /api/listings/:id/renew` — підтвердження продовження оголошення після закінчення безкоштовного періоду.
- `POST /api/listings/:id/deactivate` — ручне вимкнення оголошення користувачем.
- `GET /api/payments` — отримання історії платежів.
- `POST /api/payments` — реєстрація нового платежу.
- `GET /api/users/me` — інформація про поточного користувача.
- `GET /api/chats` — перелік чатів користувача з останнім повідомленням і лічильниками непрочитаних.
- `POST /api/chats` — створення (або повторне відкриття) діалогу щодо оголошення з опціональним стартовим повідомленням.
- `GET /api/chats/:id` — отримання чату з усією історією повідомлень.
- `POST /api/chats/:id/messages` — надсилання нового повідомлення в чат.
- `POST /api/chats/:id/read` — позначення усіх повідомлень як прочитаних для поточного користувача.
- `POST /api/chats/:id/archive` — архівація чату учасником.

### Наступні кроки
- Додати справжню БД (PostgreSQL/Prisma) замість файл-базованого сховища.
- Інтегрувати платіжні провайдери (Stripe, PayPal) та системи push-сповіщень.
- Розробити мобільний застосунок (Flutter) та веб-адмінку (React).
- Реалізувати повну модерацію, сегментацію push, розширені підписки та білінг.
